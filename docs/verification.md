# Spark’26 — verification evidence

Environment: Debian 13 · Node 20.20.2 · PostgreSQL 17.11 · Chrome 148 (headless) · Prisma 6.19.3
Databases: `spark26` (application) and `spark26_test` (isolated test database)

Run order: `npm test` → `npm run test:e2e` → `npm run test:camera`

a `BOTH`-mode event accepts website **and** on-spot registrations while still refusing a duplicate.

Additional security checks: bcrypt-only hashes, no user enumeration, no public admin signup,
disabled admins lose access, HTTP-only/SameSite cookie, role enforcement (SCANNER cannot publish),
student-to-student data isolation, rate limiter engagement, no internals in errors, audit log hygiene,
upload traversal guards.

## 3. Camera QR scan — `npm run test:camera`

Chrome is fed a synthetic camera stream (Y4M) containing a genuine pass QR for a student who just
registered. The admin opens the scanner, starts the camera and the app decodes the code:

```
prepared pass SP26-E07-UJFYHZ for Camera Check Student @ Paper Presentation (E07)
camera started: true
scan result: Present · Camera Check Student SP26-E07-UJFYHZ · CAM26450 · Computer Science and
             Engineering · Year II · Section B · Checked in 11 Oct 2026, 12:08 pm
✓ camera QR scan → attendance verified
```

Screenshot: `var/e2e-shots/08-camera-scan.png` (camera view + green “Present” result + toast).
